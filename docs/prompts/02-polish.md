Подобряваме външния вид и професионализма на репото photo-to-3d. Прочети първо README.md, docs/PLAN.md (секции 1, 2, 4 и 15), docs/benchmarks.md и `git log --oneline`. Работата е само по репото и документацията. Приложението (FastAPI/Electron) НЕ е част от тази задача.

## Състояние сега
- Репото е локално, клон `master`, 8 commit-а, работното дърво е чисто. Няма remote и още не е качено в GitHub. Предстои да е ЧАСТНО репо sako4018/photo-to-3d, но `gh` още не е влязъл в акаунт. Нищо не качвай и не създавай в GitHub.
- Код: `engine/` (Python 3.11, uv, PyTorch, вграден TripoSR в `engine/src/photo3d_engine/engines/triposr_vendor/` с негов LICENSE и NOTICE.md). CLI: `uv run --project engine photo3d make снимка.jpg --height 50`, резултатът е в `out/<име>/` (original, STL, report.txt, details/).
- `out/` е в .gitignore, затова картинките за README трябва да са малки и да се пазят в `docs/images/`.
- Тестове: `cd engine && uv run pytest` (96 бързи). Бавните (`-m slow`) ползват истински модел и не трябва да вървят в CI.
- Липсват: LICENSE, CI, картинки в README, английски README, раздел "Ограничения", docs/decisions/, метаданни в pyproject.

## Правила
- Първо ми дай кратък план: списък на файловете, които ще създадеш или променяш, и как ще направиш картинката. Изчакай моето "да".
- Работи по точките една по една. След всяка я провери: пусни `uv run pytest`, `uv run ruff check .` и `uv run ruff format --check .` от `engine/`, отвори картинките и ги прегледай. Покажи ми картинките, преди да ги ползваш. Не твърди, че нещо работи, без да си го пуснал.
- Нищо не измисляй в документацията: числата идват от docs/benchmarks.md. Ако нещо не е проверено, пиши го като непроверено.
- Не пипай логиката на engine/ (кода в src/). Единственото изключение са метаданните в pyproject.toml.
- Не комитвай и не пуш-вай без мое изрично "да". Предложи commit-и по една логическа стъпка (LICENSE; CI; картинки + README; README.en; decisions; метаданни), със съобщения на английски. Автор: Sarkis Demirdjian <sarkdemi@gmail.com>, клон master. Преди commit пусни `git config user.email` и ползвай skill-а safe-commit.
- Преди да презапишеш файл, покажи ми какво има в него. Не трий файлове.
- Накрая провери със свеж клон (`git clone` в отделна папка), че всичко комитнато работи: тестовете минават и README картинките се показват (пътищата са относителни и файловете са в git, а не са игнорирани от .gitignore).
- Отговаряй ми на български. Кодът, коментарите, имената на файловете и commit съобщенията са на английски. README.md е на български, README.en.md на английски.
